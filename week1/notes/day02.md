# Day 2 笔记

1. 模型本身是**无状态**的。它"记得"上一句，是因为每一轮请求都把**全部聊天记录**（整个 messages 列表）重新发给了它——记忆在程序手里，不在模型里。

2. messages 的三种角色：**system** 是开场写死的设定（人设/约束，只出现一次）；**user** 是用户说的话；**assistant** 是模型说的话（由 TODO 5 写回记忆）。角色标签必须和说话的人一致，标错会在很远处爆炸。

3. 聊了 5 轮后，第 6 次请求的 messages 里（不算 system）共有 **10 条**消息：每轮增加 user 一条 + assistant 一条。

4. 聊得越久，每次请求的输入 token 越多，费用越高——第 N 轮的输入约等于前面全部轮次之和。

5. 想让它"忘掉"前面的内容：**只发你想让它看到的那些消息**。开新窗口是特例（= 发一个空列表）；也可以只发最近几条、把旧对话压缩成一条摘要。发什么的决定权 100% 在代码手里——这就是上下文工程的入口。
