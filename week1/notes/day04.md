# Day 4 笔记

1. `json.loads(text)` 的输入是**JSON 格式的字符串**（就是模型那段"文字"），输出是**字典/列表**——程序从此可以按键取货，不再肉眼读话。

2. 模型爱给 JSON 裹上**代码围栏**（```json ... ```），咬第一口（`json.loads`）前要先**拆围栏/洗白**。今天的实战补充：这次围栏没出场（模型交了裸 JSON）——概率生物偶尔守纪，预案留着，Day 6 工具调用的 JSON 更大，它大概率会来。

3. 提示词里写了「只输出 JSON」仍要程序端防备的核心理由：**模型输出是概率的**，没有任何格式保证。今天的实锤：两次调用同一句话，`minutes` 一次 30、一次 20——**结构化输出只保证形状（JSON 合法），不保证语义（数值对不对）**，所以程序端永远要有第二层校验。

4. 两种约束方式的区别：**prompt 约束是「说服」（大概率守约，但可能话痨、可能裹围栏）；JSON mode 是「管束」（服务端约束解码，物理上只产出合法 JSON 语法，不保证你的 schema）**。实测：本接口（opencode go）支持 `response_format={"type": "json_object"}`（2026-10-31）。工程实践：两者配合 + 程序端校验，三层防线。

5. 累加器：昨天 `full = full + text` 攒**对话文本**，今天 `total = total + task["minutes"]` 攒**总分钟数**——同一个套路。正式评价：**大问题化成一地小步，每步只结算自己这一份，从不回头重算**。Day 5 的错误计数、成本累计都靠它。

## 今天真正记住的一件事

结构化输出保形状不保语义——JSON 合法只是第一层，数值对不对要程序自己校验。
