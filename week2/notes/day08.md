# Day 8 笔记

1. 今天用了第一周的哪三个旧技能？chat.py → **messages 剧本结构 + while 输入循环**；structured.py → **让模型输出 JSON（json.loads 取货）**；cost_log.py → **重试机制**（for attempt in range(3) + try/except）。花费统计这版没做——那是明天可以加的功能。

2. JSON Lines（`.jsonl`）和普通 JSON 文件比，好处是**一行一条、追加不重写、坏一行不毁全部**（日志式存储：读取少、追加快、出问题只损一行）。

3. 为什么在 `json.loads` 之后多加一道校验？因为 **JSON 合法 ≠ 内容有用**（Day 4 的「保形状不保语义」）。今天有实锤：「今天练了一下」返回了完全合法的 `{"exercises": []}`，校验层把它拦下。再往前一层还有 `JSONDecodeError` 兜底（模型可能裹围栏或吐歪话）。

4. 【设计题】还缺什么（教练代填，可改）：① 查历史（「我上次卧推多少？」）② 每周自动总结（训练次数、重量趋势）③ 记录/提问双模式自动判断。**圈选 ①**——它天然通向第 3 周的 RAG（用自己的训练数据当语料）。

5. 一次记录的开销（实测）：**输入 171 / 输出 164，合计 335 token ≈ 0.001654 元**。输出和输入一样贵，因为每个动作的完整字段（含 null）都要逐个写出来——结构化输出贵在写入侧。

## 今天真正记住的一件事

JSON 合法不等于内容有用——校验层要验的是「里面有没有我要的东西」。

## 文档对账（structured_output.md，2026-11-04 晚）

三个约束方式我都摸过实物，但深度不同：

1. **方式一：Prompt 约束** —— structured.py 和今天的记录器都在用（SYSTEM_PROMPT 手写格式）。见过的失败模式：围栏风险、同一句话两次语义不同（30/20 分钟）、合法但空的 `exercises`。简单场景够用，靠概率守约。
2. **方式二：Schema + 验证 + 重试** —— 我只做了半套：「验证」有了（JSONDecodeError 兜底 + exercises 非空检查，手写 if，不是真正的 schema 对象）；「重试」没有——失败后是让用户手动重来。
3. **方式三：原生结构化输出** —— Day 4 测过 `json_object`（只保语法合法）；今晚补测 `json_schema(strict)`：**这个接口支持**，输出形状 100% 合规。但同一发实验给出今天最重的一课：prompt 没喂日期时，它输出了 `"date": "2026-05-07"`——形状完美的错误答案。**约束越强只是把错误包装得越工整；事实要靠模板插槽喂进去，不能靠模型猜。**
4. **Pydantic / Instructor**：先停放——字段还少，手写 JSON 够用；等模型长到 6+ 字段或第 3 周以后再引入。

→ 明天动手升级（小改动）：① API 层直接上 `json_schema` 严格模式，围栏风险彻底退役；② 保留语义校验（exercises 非空），并把「校验失败」接上自动重试一次——把方式二补完整。
